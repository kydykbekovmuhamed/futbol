# Приложение для бронирования футбольных площадок — концепция и roadmap

## 1. Суть продукта

Платформа-агрегатор футбольных площадок города (футзалы, поля с искусственным газоном, стадионы) с бронированием в реальном времени, задатком, подтверждением от администратора площадки и последующим развитием в социальную платформу для футбольного комьюнити.

Потенциальный охват: **342 площадки** в городе — при полном покрытии рынка это создаёт эффект монополии/сетевого эффекта, поскольку и игроки, и владельцы площадок заинтересованы быть там, где есть все остальные.

---

## 2. Ключевые пользовательские сценарии

### 2.1. Поиск и бронирование
- Клиент выбирает **время** (например, 14:00–15:00), а не сначала конкретную площадку — система показывает **все свободные площадки** на этот интервал.
- Фильтры: район/локация, тип покрытия (зал/газон/стадион), цена за час, вместимость (5x5, 7x7, 11x11).
- Для занятых площадок — отображается **таймер до освобождения** ("освободится через 23 мин"), а не просто "занято".
- Формат поиска: конкретный день+час, либо сетка на ближайшие 7 дней для гибких по времени игроков.

### 2.2. Подтверждение брони (гибридная модель)
- Клиент бронирует и **резервирует** (не списывает) задаток.
- Администратору площадки одновременно приходит push-уведомление **и** автозвонок/SMS.
- Подтвердить можно любым каналом: тап в приложении **или** ответ на звонок (фиксируется через IVR/оператора).
- Таймер подтверждения: 5–10 минут, отсчёт с момента брони. За 2 минуты до истечения — повторное уведомление админу.
- Если ни один канал не сработал за отведённое время — бронь автоматически снимается, hold на задатке снимается (без ручного возврата).
- MVP: слот возвращается в свободные, клиенту — уведомление с предложением попробовать другое время/площадку.
- Версия 2: автоматическое предложение 2–3 похожих слотов при отказе (перебронирование в один тап).

### 2.3. Продление игры
- За 10–15 минут до конца текущего слота — push клиенту "продлить ещё на час?".
- Если он не ответил и не продлил — слот открывается для новых броней.
- Важно: следующий потенциальный клиент не должен успеть перехватить слот в момент, пока текущий игрок принимает решение — система придерживает слот на паузе.

### 2.4. Роль администратора площадки
- Роль "администратор площадки" — не привязана к конкретному физлицу (владельцу), а является системной ролью, назначаемой на каждую площадку. Это необходимо для масштабирования на 342+ площадки.

## 3. Монетизация

| Источник | Описание | Когда вводить |
|---|---|---|
| Подписка площадок | Доступ к календарю, приёму брони, аналитике заполняемости. Тиры: базовый / продвинутый | Старт — низкий порог входа для быстрого охвата рынка |
| Комиссия с брони | % от задатка/оплаты за онлайн-бронирование (условно 5–10%) | Через 3–6 мес, когда объём онлайн-брони станет заметным |
| B2B турнирные пакеты | Комиссия за организацию турниров + продажа пакета "площадки + судейство + статистика + награды" | Этап 2, вместе с запуском корпоративных турниров |
| Спонсорство турниров | Реклама спортивных брендов на турнирах и в приложении | Этап 2–3, при достаточной базе активных пользователей |
| Реклама брендов | Баннеры, нативная геймификация, партнёрка, таргетинг по данным (детали — раздел 3.1) | Этап 2–3, требует измеримой активной базы |
| Подписка игроков/команд | Расширенная статистика, приоритетный мэтчмейкинг, бейджи | Этап 3, когда комьюнити-слой наберёт активность |

Референсы по модели: Bookeo, Playtomic (маркетплейсы бронирования спортивных площадок) — используют связку "низкая базовая подписка + комиссия с онлайн-брони".

---

## 3.1. Реклама брендов (детализация)

Отдельный источник дохода, актуальный **только при наличии измеримой активной базы пользователей** — до этого момента бренды не платят за размещение с малым охватом. Реалистично — Этап 2–3, после запуска комьюнити-слоя (рейтинг, турниры).

| Формат | Описание |
|---|---|
| Прямые размещения | Баннер на главном/в поиске площадок, спонсорская плашка в push, логотип на профиле команды/турнирной таблице |
| Спонсорство турниров | "Турнир при поддержке [бренд]" — призовой фонд, форма с логотипом, присутствие в приложении/на площадке/в анонсах. Хорошо стыкуется с корпоративным сегментом (см. раздел 4) |
| Нативная геймификация | Номинация "MVP тура от [бренд]" с призом, брендированные бейджи/ачивки — встроено в то, ради чего пользователь и так открывает приложение |
| Партнёрка/реферальные комиссии | % с покупок по ссылке (спортивные магазины), страховка от травм в момент бронирования, доставка воды/формы на площадку |
| Таргетированная реклама по данным | Уникальный датасет (гео, частота игр, уровень команды, тип покрытия) — ценность для локальных рекламодателей (магазины, фудкорты, такси рядом с площадками); продаётся таргетинг, а не просто показы |

## 4. Корпоративные турниры

- Организатор (HR компании или оператор платформы) создаёт турнирную сетку — блок бронирования на нескольких площадках под несколько команд.
- Предоплата турнирного пакета целиком, а не отдельные задатки за каждую бронь.
- Используется инфраструктура турниров и рейтинга из комьюнити-слоя, с турнирной таблицей поверх обычных броней.
- **Открытый вопрос**: отдельная точка входа (лендинг/инструмент для HR) или раздел внутри основного приложения — сегменты "обычный игрок" и "корпоративный заказчик" имеют разное поведение и разные каналы привлечения.

### 4.1. Self-service модель турнира ("... при поддержке [бренд], призовой фонд...")

Платформа объявляет турнир под брендом-спонсором, команды сами регистрируются, сами платят взнос за участие, сами оплачивают газон под своё время по турнирной сетке.

**Три раздельных потока платежей:**

| Поток | Кому идёт | Назначение |
|---|---|---|
| Взнос за участие команды | Оператору платформы | Формирует призовой фонд (частично/полностью) + комиссия организатора |
| Оплата газона | Площадке (обычная бронь из ядра продукта) | Аренда конкретного слота по турнирной сетке |
| Спонсорский взнос бренда | В призовой фонд и/или оператору | Плата за размещение бренда + пополнение призового фонда |

**Монетизация организатора:**
- Комиссия с взноса за участие каждой команды (ориентир 10–15%, отдельный тариф от обычной брони)
- Фиксированная плата от бренда за "турнир при поддержке [бренд]"
- Обычная комиссия площадки с бронирований по турнирной сетке (без изменений от ядра продукта)

**Архитектурная развилка**: взнос за участие и оплата газона — раздельные платежи (проще технически, площадке не важно происхождение брони) или единый "турнирный пакет" (удобнее команде — платит один раз, но оператору нужно потом рассчитываться с каждой площадкой по фактически сыгранным матчам).

**Вопросы механики регистрации:**
- Минимальное число команд для старта турнира — и что происходит с взносами, если турнир не набрался
- Дедлайн регистрации и автогенерация сетки после набора команд
- Неявка команды на свой слот по сетке (не оплатила/не забронировала газон вовремя) — техническое поражение с потерей взноса, или перенос

## 5. Контент и удержание (что делать, чего избегать)

**Делать (дёшево, юридически чисто, работает на удержание):**
- Персонализированные push: статус брони/игры, приглашение продлить, "твоя команда поднялась в рейтинге", "тебе бросили вызов"
- Лента активности комьюнити (вызовы на матч, поиск пятого игрока рядом)
- Расписание и результаты местных турниров (собственные данные платформы — свободный контент)
- Агрегация футбольных новостей одной строкой (заголовок + ссылка на источник, без копирования полного текста)
- Геймификация: рейтинг, номинации, прогресс до следующего "звания"

**Не делать (высокий риск / низкая отдача):**
- Трансляции ЧМ и топ-турниров (АПЛ, Лига Чемпионов и т.п.) — права стоят дорого и продаются эксклюзивно по странам; показ без лицензии — нарушение авторских прав
- Глубокий новостной раздел как самостоятельная ценность — это ниша специализированных приложений (ESPN, Sports.ru и т.п.), не даёт эффекта удержания сравнимого с персональными уведомлениями

Реалистичная альтернатива трансляциям: интеграция расписания матчей (открытые данные, без лицензии) + партнёрские ссылки на легальные OTT-сервисы, у которых уже есть права.

## 6. Этапы разработки

### Этап 1 — MVP (ядро)
- Бронирование по времени с показом всех свободных площадок
- Гибридное подтверждение (push + звонок, hold на задатке, автовозврат по таймеру)
- Продление игры с защитой слота от перехвата
- Роль администратора площадки как системная сущность
- Подписочная модель для площадок (низкий порог входа)

### Этап 2 — Комьюнити и B2B
- Профили команд, статистика игр
- Поиск соперника / поиск игрока в состав
- Рейтинг команд и игроков, номинации
- Корпоративные турниры (турнирные сетки, B2B-пакеты)
- Комиссия с онлайн-брони, спонсорство турниров

### Этап 3 — Удержание
- Персонализированная лента активности
- Push-уведомления на основе поведения (рейтинг, вызовы, прогресс)
- Расписание/результаты местных турниров
- Лёгкая агрегация новостей
- Подписка для игроков/команд (расширенная статистика)

## 7. Идеи для будущих версий (банк идей, не для MVP/Этапа 2)

Продукт по сути развивается в супер-апп для любительского футбола. Полезные референсы из индустрии:
- **Playtomic / Matchi** — маркетплейсы бронирования спортивных площадок (падел/теннис/футбол) в Европе: поиск по времени, все свободные площадки на карте, подписка+комиссия, механика "открытые игры" (вступить в чужую забронированную игру, если не хватает состава)
- **Veo / Pixellot** — автоматические камеры с ИИ-трекингом мяча, которые сами снимают и монтируют видео матчей
- **EA FC Ultimate Team** — механика прогрессии и коллекционирования карточек игроков (не сама игра, а именно паттерн вовлечения)

**Конкретные идеи:**

| Идея | Суть |
|---|---|
| Рейтинг по системе ELO | Рейтинг растёт сильнее за победу над сильным соперником — честнее обычного счёта побед/поражений, даёт мэтчмейкинг "по силам" |
| Карточки игрока (в духе FUT) | Персональная карточка с фото, позицией, статистикой, визуальным рейтингом — виральный контент для соцсетей |
| Live-счёт матча | Капитан/судья вводит голы в реальном времени, друзья следят за live-табло удалённо |
| Видео с площадок | Даже без ИИ-трекинга — статичная камера, нарезка клипов по времени брони (данные уже есть в системе). Платная опция записи — доп. доход |
| Динамическое ценообразование | Цена выше в пиковые часы (18:00–21:00 будни), ниже в непопулярные — лучше загрузка площадок вне пика, больше объём бронирований |
| Кошелёк/бонусные баллы | Кэшбэк с брони в баллы, тратятся на будущие игры/турнирные взносы — удерживает деньги в экосистеме |
| Погодная интеграция | Автопредупреждение/перенос при дожде для площадок без крыши — снижает споры о возврате задатка |
| Судьи как маркетплейс | Раздел "нанять судью" — фрилансеры-рефери регистрируются, команды бронируют вместе с площадкой — доп. комиссия. Детали механики — раздел 7.1 |

**Предостережение**: продукт уже включает три больших домена (бронирование, комьюнити, турниры) — эти идеи добавляют четвёртый (медиа/видео) и усложняют остальные. Держать как банк идей на будущее, не пытаться включить в MVP или Этап 2.

### 7.1. Маркетплейс судей (детализация)

**Механика:**
- Судья регистрируется отдельной ролью — профиль с опытом, категорией/лицензией (если в стране есть официальная сертификация), отзывами, ценой за матч/час
- Команда/организатор турнира при бронировании площадки или турнирного слота видит доступных судей на это время и бронирует их вместе со слотом — как допуслугу, без отдельного поиска
- Оплата по той же схеме, что и задаток за площадку: hold при бронировании → списание после подтверждения судьёй → автовозврат при отмене (см. раздел 2.2)

**Монетизация:** комиссия с каждой оплаты судье (ориентир 10–15%) — доход почти без затрат со стороны платформы, услугу выполняет сам судья. Для судей это тоже стимул регистрироваться — доступ к потоку клиентов вместо самостоятельного поиска.

**Что продумать:**
- Рейтинг/отзывы судей — как у водителей в такси-приложениях, единственный способ команд доверять незнакомому судье
- Неявка/опоздание судьи — нужна та же логика подтверждения/таймаута, что у администраторов площадок, иначе матч без судьи срывает турнирное расписание
- Верификация судей (документы/лицензия) перед допуском — особенно важно для официальных корпоративных турниров, где важна легитимность результата

### 7.2. Раздел "Магазины" в меню

Отдельный пункт навигации — каталог локальных магазинов спортивной экипировки и около-спортивных услуг (массаж/физио, спортивное питание, страховка от травм) и брендов.

**Формат:** витрина-агрегатор, не e-commerce внутри приложения — каждый магазин отдельной карточкой (лого, описание, локация на карте, промо/скидка), переход на сайт/WhatsApp/номер магазина. Не требует своего склада или доставки.

**Монетизация (не взаимоисключающие варианты):**

| Вариант | Суть | Когда вводить |
|---|---|---|
| Платное размещение | Магазин платит за присутствие/позицию в каталоге (аналог подписки площадок) | Когда у платформы уже есть трафик, интересный магазинам |
| Комиссия за переход/покупку | Партнёрская ссылка с UTM-меткой, % с продажи | Требует интеграции с магазином — сложнее технически |
| Промокоды | Скидка только для пользователей приложения (например "-10% по коду FUTBOL10") | Реалистичный старт — просто отследить по коду, не требует интеграции |

**Точки интеграции в существующие сценарии:**
- Промо магазина в момент бронирования ("забыл бутсы? -10% в [магазин] рядом с площадкой")
- Ссылка на магазин в профиле игрока/команды (партнёрка, раздел 3.1)
- Магазин как спонсор турнира с призами/скидочными купонами участникам (раздел 4.1)

## 8. Открытые вопросы

1. Как отличать в UI/статистике "админ отклонил бронь" от "админ не ответил" — нужно ли это разделять для клиента, или результат подаётся одинаково ("слот недоступен")?
2. Поддерживает ли выбранный платёжный провайдер в Кыргызстане механизм hold (резервирование без списания), или нужно продумывать альтернативную схему задатка?
3. Корпоративные турниры — отдельная точка входа для HR/офис-менеджеров, или раздел внутри основного приложения?
4. Слой комьюнити (рейтинг, поиск команд) — в MVP сразу, или строго вторая волна после того как ядро бронирования наберёт площадки?
